# Screenly 1.7 — закрытая онлайн-бета (Windows + Render)

> **Режим: только приглашённые тестировщики.** Не объявляй запуск для всех, особенно 13–17 лет: текущая возрастная группа выбирается самим пользователем, защита трансляций и работа модераторов для публичного сервиса не проверены.

## Шаг 0. Сделай резервную копию

На Windows останови старый Screenly (`Ctrl + C`) и **сохрани отдельно** старый `.env.local` и `data\screenly.json` (если уже есть аккаунты). **Никогда не загружай эти файлы на GitHub и не присылай их в чат.** Для переноса данных в PostgreSQL есть отдельный шаг ниже.

## Шаг 1. Подготовь проект

1. Распакуй ZIP в папку, например `C:\Screenly_1.7` (не запускай прямо из архива).
2. Перенеси старый `.env.local` рядом с `package.json` только для локального тестирования.
3. Открой PowerShell внутри распакованной папки и введи:

```powershell
npm.cmd install
npm.cmd run check
npm.cmd run build
npm.cmd run dev
```

Проверь `http://localhost:3000`. Если видишь `Ready` и можешь войти по коду, останови сервер (`Ctrl + C`).

## Шаг 2. Подготовь GitHub

1. Создай **приватный** репозиторий `screenly` на GitHub.
2. Загрузи в него **содержимое распакованной папки**. Не загружай `.env.local`, `data\screenly.json`, `node_modules` и `.next`; они внесены в `.gitignore`.
3. После загрузки проверь, что перечисленных файлов с секретами в репозитории нет.

Можно использовать GitHub Desktop: `File → Add local repository` (при необходимости создать репозиторий в папке), `Commit to main`, `Publish repository` с выбором **Private**.

## Шаг 3. Создай PostgreSQL в Render

1. Открой [dashboard.render.com](https://dashboard.render.com/).
2. Создай сервис **Postgres** для `screenly-beta` в выбранном регионе. Посмотри актуальные условия тарифа — базы данных и хостинг могут стоить денег.
3. В настройках базы найди её **Internal Database URL**. Если веб-сервис будет в этом же регионе и аккаунте, используй именно внутреннюю ссылку. **Не публикуй её**.
4. Сохрани её для переменной `DATABASE_URL` веб-сервиса.

## Шаг 4. Создай веб-сервис

В Render выбери **New → Web Service** и подключи приватный репозиторий GitHub.

- Runtime / Language: `Node`.
- Build Command: `npm install && npm run build`.
- Start Command: `npm run db:init && npm run start:hosted`.
- Health Check: `/api/health`.
- Instances: **одна** для первой закрытой беты; формат JSONB с общей строкой рассчитан на небольшой поток и не заменяет нормализованную БД для больших нагрузок.
- Region: тот же, что у PostgreSQL.

В разделе **Environment** внеси следующие **девять** переменных:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Internal Database URL из Render Postgres |
| `SITE_ORIGIN` | Точный адрес твоего веб-сервиса с `https://`, например `https://screenly-private-beta.onrender.com` |
| `LIVEKIT_URL` | Прежний `wss://...livekit.cloud` |
| `LIVEKIT_API_KEY` | Прежний серверный API Key |
| `LIVEKIT_API_SECRET` | Прежний API Secret |
| `ALPHA_ACCESS_CODE` | Длинный **новый** код для приглашённых тестировщиков |
| `ALPHA_SESSION_SECRET` | Длинный случайный секрет (минимум 32 символа) |
| `ROOM_SIGNING_SECRET` | Другой длинный случайный секрет (минимум 32 символа) |
| `NODE_ENV` | `production` (обычно Render задаёт его автоматически, но лучше проверить) |

На странице сервиса Render будет выдан `https://...onrender.com`. **SITE_ORIGIN должен в точности соответствовать ему**, без завершающего слеша. Если адрес выяснился только после создания сервиса, добавь переменную и повторно разверни.

Для генерации нового кода и двух секретов на компьютере:

```powershell
node scripts/generate-secrets.mjs
```

Не используй публично код со старых скриншотов. Браузерные переменные `NEXT_PUBLIC_*` для этих секретов **не нужны**.

После успешного запуска открой `https://твой-сайт.onrender.com/api/health`. Должно появиться `{"status":"ok"}`.

## Шаг 5. Перенос существующих аккаунтов (необязательно)

**Если у тебя есть аккаунты в Screenly 1.6**, перенеси их *до приглашения новых пользователей*.

1. Сделай копию старого `data\screenly.json` вне GitHub.
2. Убедись, что новая облачная база ещё пуста (не регистрируй новых пользователей).
3. Для импорта со своего Windows компьютера нужна **External Database URL** Render PostgreSQL, с TLS (`sslmode=require`). Временно добавь её в локальный `.env.local` как `DATABASE_URL`. Не путай с внутренней ссылкой, доступной только с Render.
4. Открой PowerShell в новой папке Screenly и запусти:

```powershell
npm.cmd run db:import -- --file "C:\путь\к\screenly.json" --confirm-empty
```

Скрипт **откажется перезаписывать непустую базу**. Прежде чем импортировать, проверь, что путь верный. По окончании удали внешний DATABASE_URL из локального `.env.local`, если он больше не нужен.

Если пользователи уже начали работать на облачном сайте — **не запускай импорт поверх живых данных**. В этом случае нужна отдельная миграция с объединением записей.

## Шаг 6. Закрытый онлайн-тест

1. Открой сайт по HTTPS в двух браузерах или на двух разных ПК.
2. Войди по закрытому коду, создай два отдельных тестовых аккаунта.
3. Проверь приглашение в приватную комнату, голос, экран и текстовый чат.
4. Создай тестовую работу в галерее, добавь друга и отправь сообщение.
5. Перезапусти веб-сервис и убедись, что данные сохранились.
6. Проверь жалобы, блокировки и модераторский доступ **до** расширения аудитории.

При ошибке смотри **Render → Logs**, не копируй сюда API-ключи, DATABASE_URL или сессионные cookies.

## Важно

- `localhost:3000` — только твой компьютер; `https://...onrender.com` — закрытая онлайн-бета на хостинге.
- Наша защита сейчас — код альфы, приглашения в приватные комнаты и разделение самозаявленных возрастных групп. Это **не готовая защита для публичной социальной сети 13+**.
- Не выкладывай сайт в открытый доступ до надёжной возрастной безопасности, работающей модерации, политики конфиденциальности и независимой проверки безопасности.
- Не передавай права администратора другим тестировщикам без необходимости.
- Временные рисунки на трансляциях не сохраняются в PostgreSQL.
