# Screenly 2.0 — Desktop Release

**Завершённая версия для закрытого использования на ПК.** Публичный массовый запуск и открытый доступ для несовершеннолетних требуют отдельных проверок безопасности, модерации и правовых условий.

Сохраняются функции версии 1.9: комнаты LiveKit, голос, демонстрация экрана, несколько потоков, указки и рисунки по разрешению владельца, профили, друзья, переписки, приглашения, галерея работ и творческие категории.

## Что нового

- Cloudflare Turnstile на регистрации: проверка в браузере и обязательная верификация Siteverify на сервере, если заданы `NEXT_PUBLIC_TURNSTILE_SITE_KEY` и `TURNSTILE_SECRET_KEY`. Токен однократный; при ошибке регистрация не проходит. Для Render настрой виджет на hostname из `SITE_ORIGIN`, например `screenly-dfar.onrender.com`. Обе переменные задаются в Render Environment, не в GitHub. Это дополнение не отменяет лимитов попыток и требований к закрытому запуску.

- Завершение комнат теперь инициирует удаление активной сессии LiveKit; при ошибке внешнего сервиса пользователь увидит предупреждение.
- Добавлены автоматические тесты преобразования URL LiveKit и реальный HTTP smoke-test основных сценариев.
- Интерфейс Screenly теперь рассчитан только на ПК и ноутбуки. Мобильные посетители увидят отдельную информационную страницу.
- Лимиты запросов API и выдачи токенов LiveKit учитывают отдельные пользовательские сессии, сохраняя общий защитный предел.
- Проверки адаптации под мобильные устройства отложены: это **ограничение интерфейса, не криптографический или сетевой запрет**. Мобильный клиент технически может обращаться к API, если имеет действующие разрешения.
- Реальные ограничения размера JSON-запросов, даже без `Content-Length`; безопасные сообщения о внутренних ошибках.
- Лимиты попыток входа/регистрации по адресу учётной записи, плюс общий защитный предел.
- Ограничение времени SQL-запросов, ручное резервное копирование состояния через `npm run db:backup`.
- Доработаны проверки API и совместимость существующей PostgreSQL-базы — данные 1.9 не сбрасываются.
- Отмена своего последнего штриха поверх выбранной демонстрации без удаления рисунков других людей.
- Полноэкранный просмотр совместной демонстрации.
- Понятный индикатор переподключения LiveKit и счётчик непрочитанных сообщений при скрытом чате.
- Улучшение управления инструментами на небольших экранах.
- Приглашения друзей в собственные комнаты, отдельный раздел уведомлений с автоматическим обновлением каждые 20 секунд.
- Организатор может закрыть комнату прямо из неё, а список участников теперь сворачивается.
- Адаптивные элементы управления комнатой, приглашениями и более заметная клавиатурная навигация.
- Приглашения ограничены друзьями одной возрастной группы; закрытие комнаты отзывает приглашения.
- PostgreSQL-хранилище для онлайн-хостинга (`DATABASE_URL`).
- Запись состояния под `SELECT ... FOR UPDATE`, атомарные коммиты и откат при исключениях.
- Локальный режим (`data/screenly.json`) сохранён для разработки.
- `/api/health`, миграция старой JSON-базы, конфигурация Node-хостинга, Render Blueprint, HTTPS `SITE_ORIGIN`.
- Скрипт `npm run start:hosted` слушает `0.0.0.0:$PORT`, локальный `npm run dev` — `127.0.0.1:3000`.

## Как пользоваться

**Пошаговая инструкция для Windows и Render:** [`ДЕПЛОЙ_НА_RENDER_WINDOWS.md`](./ДЕПЛОЙ_НА_RENDER_WINDOWS.md).

### Локально

```powershell
npm.cmd install
npm.cmd run check
npm.cmd run build
npm.cmd run dev
```

Открой `http://localhost:3000`. Для локальной разработки перенеси старый `.env.local` и при необходимости `data\screenly.json`.

### В облаке

Создай PostgreSQL и Node Web Service (например, Render), добавь `DATABASE_URL`, `SITE_ORIGIN`, LiveKit и остальные секреты через панель хостинга.

```bash
npm install --include=dev && npm run build
npm run db:init && npm run start:hosted
```

Деплой не выполняется автоматически, настройки тарифов и доменов пользователь определяет в своём аккаунте Render.

### Резервная копия перед обновлением

На доверенном компьютере с установленным `DATABASE_URL` запусти `npm run db:backup`. Скрипт сохраняет JSON в `backups/` с ограниченными правами доступа и не меняет базу. В файле содержатся персональные данные, храни его в зашифрованном хранилище, не отправляй в GitHub или публичные чаты. Для восстановления в *пустую* базу подходит `db:import --file ... --confirm-empty` после проверки файла; существующая непустая база не перезаписывается.

### Что мешает открытому релизу

- Возраст 13–17 указывается самостоятельно: необходима независимая проверка возрастных и защитных механизмов и модерации до допуска массовой аудитории.
- Лимиты запросов пока работают в памяти одного процесса, не разделяются между несколькими инстансами.
- Общий JSONB-документ PostgreSQL — временная модель для небольшого закрытого теста; перед масштабированием нужна миграция на отдельные таблицы и нагрузочные испытания.
- Нужно проверить восстановление из резервной копии в отдельной тестовой базе, безопасность LiveKit, работу после падения сервера и обновление с реальными пользователями.

### Перенос локальных пользователей

Скрипт `db:import` импортирует старый `screenly.json` **только в пустую** подготовленную PostgreSQL-базу. Данные пользователей нельзя публиковать в репозитории.

## Ограничения и архитектурный долг

**Сейчас в PostgreSQL хранится общий JSONB-документ в одной строке.** Транзакции защищают от одновременной записи, но это компромисс для небольшой закрытой беты, а не схема для большого трафика. До масштабирования потребуется разложить пользователей, комнаты, сообщения и жалобы по таблицам, вынести лимиты запросов в Redis и наладить резервное копирование/мониторинг.

Возраст 13–17 сейчас указывается самим пользователем. Это **не надёжная проверка** и не основание открывать случайные голосовые знакомства несовершеннолетних для всех. Оставляй доступ по приглашению, проводи реальные проверки модерации и безопасности до публичного запуска.

## Проверка

`npm run check` запускает набор регрессионных тестов и тестов состояния БД. Пакеты и реальное подключение к Render/Postgres и LiveKit обязательно проверь в своей среде; тесты не доказывают готовность для публичного релиза.
